# Real historical replay and worker-outage checks

No project files, dependencies, model parameters or schema are changed. Uses the existing backend environment, application database, source key and shadow worker. These checks intentionally ingest a small amount of telemetry into the current organization.

1. Keep all three services running. Extract this folder under D:\CAPSTONE\tools and run run_real_replay.ps1. Paste the existing ls_key source key at the hidden prompt.
2. The script prepares the first 20 records of original normal_13/conn.log and normal_scanning6/conn.log, with source file/line SHA-256 hashes, original decimal timestamp and original TSV bytes retained in an ignored provenance field. It does not alter timestamps or fill missing values. The converted JSON evidence hash is distinct from the TSV source hash. These are historical real dataset records (is_simulated=false), not a live network capture, not synthetic, and not a new labelled performance benchmark.
3. Two fixed capture IDs identify this replay sample. All 40 records are posted through the source-authenticated API, read back under the resolved source/tenant, and retried immediately. Original converted JSON, hashes, simulation flag, IDs, trace IDs and stored assessments must agree. Retries must return duplicate=true without storage changes. The first 20 uploaded normal13 records have 5 shadow-eligible and 15 quality-rejected records; scanning6 has 20 eligible. Expected aggregate: 25 predictions and 15 rejected assessments, without any claim about predicted labels.
4. Local database Threat/Incident counts for this source's organization are compared before and after. If unrelated concurrent activity changes counts, the test fails rather than claiming absence of side effects. Keep the lab idle during checks.
5. Stop ONLY the model worker terminal with Ctrl+C. Leave FastAPI and frontend running. Run run_worker_outage.ps1 and provide the same key. The checker requires the worker health endpoint to be unavailable, sends one existing synthetic eligible fixture under synthetic-worker-outage-001, and requires unavailable with prediction=null. It confirms raw storage and immutable retry with unchanged tenant Threat/Incident counts. This is a distinct synthetic failure experiment.
6. Restart the worker with D:\CAPSTONE\tools\toniot-shadow\start_shadow_worker.ps1. Existing unavailable assessments remain unchanged on retries; this version does not backfill or rescore.

## Output
D:\CAPSTONE\datasets\TON_IoT\replay_checks\real-small-001 contains sample_manifest.json, two derived JSONL evidence files and real_replay_report.json. worker_outage_report.json is in replay_checks. Status complete is written only when all relevant checks pass. Existing accepted evidence remains if interrupted; real replay uses stable sample/capture identities for retry. A changed source file is detected rather than silently overwriting an existing manifest. Historical timestamps remain in 2019 while assessment timestamps reflect the current run.

The real replay creates up to 40 flow rows; its immediate retries add none. The worker-outage test creates up to one synthetic flow; retries add none. Reports list IDs and counts but never include the source credential. Keys are set only in the child process environment and removed in a finally block. Requests use fixed loopback HTTP, bypass proxies and refuse redirects.

## Validation
Three standard-library tests cover original evidence/timestamp/missingness preservation, stored-response/retry verification and rejection of changed retry assessment. Sample preparation was run on the original uploaded normal13/scanning6 logs. Full database/API failure-path verification occurs on the user's local stack. No new model accuracy, calibration, live network reliability or production readiness claim is made.
